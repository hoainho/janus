# Recall Filter — Freshness/Drift Post-Filter Contract

> Last updated: 2026-06-27
> Companion script: `scripts/recall_harden.py`
> Health index: `scripts/recall_health.json` (regenerated by the script)

---

## Why this exists

The ws-memories corpus has atoms of varying freshness. As of 2026-06-27:

- **108 unique atoms** (168 files; omo writes each atom to both the project dir and
  `_shared/atoms/` — deduplication is by atom_id)
- **34.5% stale** (>90d by `verified_at`), **14.9% aging** (31–90d), **14.9% fresh** (<=30d)
  - 32.1% have no `verified_at` → treated conservatively as stale
- **1 truly drifted** atom (applies_to repo present locally, cited file missing)
- **0 "unknown-drift"** (all applies_to repos that lack a cited file are present locally
  in this run; if a repo is absent, drift is "unknown", never "drifted")

The omo-session-distiller MCP daemon ranks by semantic similarity but cannot know if a
cited code path still exists or if a solution was superseded. This filter is a
**post-processing step** applied to any recall result list before it is acted on.

## Health index format (`recall_health.json`)

```json
{
  "<atom_id>": {
    "verified_at": "YYYY-MM-DD | null",
    "age_days": 42,
    "freshness": "fresh | aging | stale",
    "drifted": false,
    "drift_status": "ok | unknown | drifted",
    "applies_to": ["playsweeps-web"]
  }
}
```

Regenerate:

```bash
python3 scripts/recall_harden.py
# dry-run: lists retire candidates, moves nothing
# with --retire: moves drifted atoms to <atoms-dir>/<project>/atoms/_retired/
```

## freshness_rank() — the filter contract

Import and apply after any recall call that returns a list of atom_ids:

```python
from scripts.recall_harden import freshness_rank
import json

health = json.loads(Path("scripts/recall_health.json").read_text())

# hits: ordered atom_ids from omo_recall / nano-brain query (best-first)
hits = ["atom-2026-02-10-...", "atom-2026-06-06-...", ...]

reranked = freshness_rank(hits, health)
# reranked: same atoms, drifted excluded, stale down-weighted
```

### Ranking weights

| Freshness | Age (verified_at) | Rank weight | Effect |
|-----------|-------------------|-------------|--------|
| fresh     | ≤ 30 days         | 1.0         | No change |
| aging     | 31–90 days        | 0.8         | Modest down-rank |
| stale     | > 90 days         | 0.5         | Significant down-rank |
| (no date) | unknown           | 0.5         | Same as stale (conservative) |
| drifted   | any               | **excluded**| Removed from results |

Score formula: `score = (n - position) × freshness_weight`

Ties are broken by original rank (stable sort), so semantic signal is preserved within
the same freshness tier.

### Drift classification rules (conservative)

An atom is **drifted** only when ALL of the following hold:
1. Its `applies_to` repo(s) are **present locally** under the repos-root.
2. At least one cited `path:line` code reference is **not found** under any sub-repo.

If the `applies_to` repo is **absent locally**, drift is classified as **"unknown"**
and the atom is **not excluded** — this avoids false positives for external repos
(e.g., `podium-mcp` when that dir isn't checked out).

## Applying the filter in practice

### Manual recall (AGENTS.md allowlist scenario)

After `omo-session-distiller_recall(query=..., limit=5)` returns hits:

1. Load `recall_health.json` (path relative to harness-cli root).
2. Call `freshness_rank(hit_ids, health)`.
3. Present reranked results to the user with freshness label per atom.
4. Flag any stale atoms: "This atom is >90d old — verify the solution still applies."

### Automated / subagent scenario

Inject into the subagent CONTEXT block:

```
[RECALL_FILTER] After recall, apply freshness_rank() from
scripts/recall_harden.py using scripts/recall_health.json.
Exclude drifted atoms. Flag stale atoms (age_days > 90) in your response.
```

## Keeping the index current

| When | Action |
|------|--------|
| After any M2 memory write | Re-run `python3 scripts/recall_harden.py` |
| After bulk atom imports | Re-run the script |
| Weekly (or per sprint) | Re-run; review new drift candidates |
| When `--retire` is used | Manifest written to `scripts/recall_retire_manifest.json`; reversible by moving files back |

The script is idempotent: re-running overwrites `recall_health.json` in place.
Retired atoms can be restored from the manifest (`dst` → `src`).

## False positive protection

The original `recall_eval.py` reported **3.3% broken refs** (2/61 refs checked).
Both were in the `podium-mcp` atom whose repo was present locally in that run but
the specific `lib/` files were not. `recall_harden.py` confirmed this as **1 truly
drifted atom** (same atom, two broken refs in the same file). The "false positive"
concern from the task brief was for repos absent locally — those are now "unknown",
not "drifted", so they are retained in recall results.
